# Railway Deployment Quick Checklist

## Pre-Deployment (5-10 minutes)

- [ ] All code committed and pushed to GitHub
- [ ] `.env` files are in `.gitignore` (not exposed)
- [ ] JWT_SECRET generated (use `openssl rand -base64 32`)
- [ ] All API keys collected (Google, SendGrid, OpenRouter, Cloudinary)
- [ ] Tested locally with `docker-compose up`

## Deployment via Railway Dashboard (10-15 minutes)

### 1. GitHub Connection
- [ ] Create Railway account at https://railway.app
- [ ] Create new project
- [ ] Select "GitHub Repo" and authorize
- [ ] Select your `quizzy-defense` repository
- [ ] Click "Deploy Now"
- [ ] Deployment starts automatically

### 2. Add PostgreSQL Database
- [ ] In Railway project, click "New"
- [ ] Select "PostgreSQL"
- [ ] Wait for database to initialize (1-2 minutes)
- [ ] Copy auto-generated `DATABASE_URL`

### 3. Configure Environment Variables
Complete this environment variable checklist in Railway:

**Critical Variables:**
```
NODE_ENV = production
PORT = 3000
JWT_SECRET = <your-random-secret>
CORS_ORIGIN = https://<your-railway-domain>.railway.app
FRONTEND_URL = https://<your-railway-domain>.railway.app
```

**Database (Auto-provided by Railway):**
```
DATABASE_URL = <auto-generated>
```

**Optional Integrations:**
```
OPENROUTER_API_KEY = <get-from-openrouter.ai>
GOOGLE_CLIENT_ID = <get-from-google-console>
GOOGLE_CLIENT_SECRET = <get-from-google-console>
GOOGLE_REDIRECT_URI = https://<your-railway-domain>.railway.app/auth/google/callback
SENDGRID_API_KEY = <get-from-sendgrid>
SENDGRID_SENDER = noreply@yourdomain.com
EMAIL_RESET_PASSWORD_URL = https://<your-railway-domain>.railway.app/reset-password
VITE_CLOUDINARY_CLOUD_NAME = <get-from-cloudinary>
VITE_CLOUDINARY_UPLOAD_PRESET = <get-from-cloudinary>
VITE_CLOUDINARY_API_FOLDER = quizzy
```

### 4. Verify Deployment (2-3 minutes)
- [ ] Go to Railway dashboard
- [ ] Application shows green "Running" status
- [ ] Check Logs tab for success message
- [ ] Look for "Nest application successfully started"

### 5. Test Application
- [ ] Open `https://<your-railway-domain>.railway.app` in browser
- [ ] Frontend loads without errors
- [ ] Open DevTools (F12), check Console tab for errors
- [ ] Test login/signup functionality
- [ ] Test real-time features (WebSocket)

## Troubleshooting During Deployment

| Issue | Solution |
|-------|----------|
| Build fails | Check Dockerfile syntax, verify `npm run build` works locally |
| Database connection error | Ensure `DATABASE_URL` is set, PostgreSQL service is running |
| Port binding error | Change `PORT` variable to 5000 or 8000 |
| Frontend shows 404 | Check Dockerfile copies frontend dist correctly |
| CORS errors | Update `CORS_ORIGIN` to match your exact Railway domain |
| WebSocket fails | Ensure backend enables CORS and WebSocket support |
| Migrations not running | Check migration files exist in `api/src/database/migrations/` |

## Rollback Strategy

If deployment goes wrong:

1. **Quick Rollback:**
   ```bash
   railway rollback <DEPLOYMENT_ID>
   ```

2. **Via Dashboard:**
   - Go to Deployments tab
   - Click previous working deployment
   - Click "Redeploy"

3. **Manual Fix:**
   - Fix issue locally
   - Push to GitHub
   - Railway redeploys automatically (if GitHub integration enabled)

## Performance Optimization Tips

1. **Increase Memory:** Dashboard → Settings → Memory (512MB → 1GB+)
2. **Enable Caching:** Add Redis service for session/cache
3. **Database Optimization:** Add indexes to frequently queried columns
4. **Static Assets:** Use CDN for images (Cloudinary is already integrated)
5. **API Pagination:** Implement cursor pagination for large queries

## Security Checklist

- [ ] All secrets are environment variables (not in code)
- [ ] JWT_SECRET is strong and random
- [ ] API keys are kept private
- [ ] Database password is strong
- [ ] CORS_ORIGIN is specific (not *)
- [ ] SSL/TLS enabled (automatic with Railway)
- [ ] Rate limiting configured (add if needed)
- [ ] HTTPS redirect enabled (check NestJS main.ts)
